What it is

The Clinical Document Checker is an AI-assisted documentation tool for clinicians at HTPN. It takes raw clinical input — a ward round audio recording, a photo of a referral letter, or manually typed notes — and transforms it into a structured SOAP note, suggests ICD-11 diagnostic codes, assesses documentation quality, and flags medico-legal risks.

The tool is built around a Human-in-the-Loop (HITL) model: the AI does the heavy lifting of structuring and analysing clinical documentation, but a named clinician must review, edit, and formally sign off on every output before it can be downloaded or used. It is designed to reduce the cognitive and administrative burden of clinical documentation — not to replace clinical judgement.

A Retrieval-Augmented Generation (RAG) layer allows clinicians to upload a reference document — a clinical guideline, drug formulary, or protocol — so the AI's suggestions are grounded in institution-specific or MOH-approved standards, reducing hallucination on drug names, dosing, and diagnostic criteria.

7-step clinical workflow

1

Data Entry — Choose Input Mode

Three input methods: Audio Upload (.ogg, .wav, .mp3, .m4a — ward round recordings, clinician narration), Image Upload (.jpg, .png — referral letters, discharge summaries, lab reports), or Manual Text entry for direct clinical notes. Multiple images allowed in a single session.

2

Reference Document — RAG Context

Optional upload of a clinical guideline, drug formulary, or diagnostic protocol (PDF or TXT). The first ~8,000 characters are passed to the AI as grounded context, reducing hallucination on drug names, dosing, and diagnostic criteria. Clearly labelled as reference only — not patient data.

3

Transcription & Extraction Review

Extracted or transcribed text is displayed in a fully editable field. The clinician reviews and corrects before proceeding — corrections here directly improve the quality of the SOAP note and AI analysis downstream. Character count shown live.

4

SOAP Clinical Form

Auto pre-filled from the extracted text. Clinician reviews and completes all fields: Subjective (chief complaint, HOPI), Objective (vitals: BP, PR, Temp, RR, SpO₂, Glucose, GCS, Weight; plus investigations and imaging), Drug List (name, dose, route, frequency, duration), Assessment (diagnosis and issue list), and Plan (short-term 24–72h and long-term/discharge plan).

5

AI Analysis — 4 Output Layers

Single button triggers the full pipeline (20–40 seconds): AI-Generated SOAP Note (structured S/O/A/P), ICD-11 Coding (AI-suggested codes with confidence scores), Documentation Quality Assessment (completeness and clarity scoring), and Medico-legal Risk Flags with targeted recommendations. All outputs are editable before sign-off.

6

Clinician Sign-off — HITL Mandatory

Full name, designation/specialty, MMC registration number, department/ward, and date/time of sign-off are required. Clinician selects review status: Approved as-is, Approved with modifications, or Partial approval — further review needed. Outputs then unlocked for download as .TXT, .DOC, or clipboard copy for EMR paste.

7

Feedback Submission

Clinician rates the tool via Likert scale (1–5) across features: SOAP generation, ICD-11 coding, documentation checker, medico-legal flags, audio transcription, image OCR, RAG reference, sign-off workflow, and overall experience. Submission can be anonymous. All feedback goes directly to Dr Naim to inform development.

AI capabilities in detail

🎙️

Audio Transcription

Clinician narration or ward round audio recordings (.ogg, .wav, .mp3, .m4a) are transcribed automatically. Audio files are processed locally and deleted immediately after transcription — no audio data is retained.

🖼️

Image OCR & Extraction

Photographs of referral letters, discharge summaries, and lab reports are read by the AI, with key clinical information extracted and structured automatically into the SOAP form fields.

🩺

SOAP Note Generation

Produces a fully structured Subjective / Objective / Assessment / Plan note from the extracted clinical data — formatted to the standard expected in Malaysian government hospital documentation.

🏷️

ICD-11 Auto-coding

Suggests ICD-11 diagnostic codes with confidence scores based on the assessment and diagnosis list. Explicitly flagged for verification against the official ICD-11 browser before use in documentation.

📊

Documentation Quality Assessment

Evaluates the completeness, clarity, and structure of the clinical note — flagging gaps, ambiguous entries, or missing mandatory fields that could affect audit quality or medico-legal standing.

⚠️

Medico-legal Risk Flags

Identifies documentation risks — missing consent records, absent allergy documentation, unclear drug orders, undocumented clinical reasoning — and generates targeted recommendations for each flagged item.

Outputs & export

All outputs require clinician sign-off before they are available for download. Three export formats are supported:

⬇ Download .TXT ⬇ Download .DOC 📋 Copy to Clipboard 📁 Session Document Log

For EMR upload, the copy-to-clipboard function allows direct paste into any hospital EMR system. Signed documents are also retained in a session document log for re-download within the same session. No data is transmitted to external servers — the AI call uses the clinician's own API key, entered at session start and not stored.

Privacy & safety by design

🔑

Session-only API keys. Clinician enters their own API key at session start. Keys are held in memory for the session only — never stored or transmitted.

🎙️

Audio deleted immediately. All audio files are processed locally and deleted right after transcription. No audio is retained on any server.

🚫

No patient identifiers. Users are explicitly advised not to enter full name or IC number. The tool is designed for de-identified or anonymised clinical content.

✍️

Mandatory HITL sign-off. No output can be exported without a named clinician providing their MMC number and formally approving the content.

💬

Anonymised feedback. Clinician feedback can be submitted anonymously — role and department are optional. No patient data is included in feedback.

📖

RAG reference only. The uploaded reference document is used purely for AI context grounding — it is not stored, indexed, or associated with any patient record.

Tech stack & research context

Built by Dr Naim and deployed on Vercel. The AI analysis pipeline runs against the Claude API — the clinician provides their own API key at session start, meaning no centralised data processing occurs outside the clinician's own authenticated session. The RAG implementation passes the first ~8,000 characters of the reference document as context in the API call, grounding the model's responses in institution-specific guidelines.

This is currently a research and feasibility prototype. The feedback loop — with Likert ratings across 9 specific tool features — is the primary research instrument, generating validity and usability data to determine whether full clinical deployment is appropriate. ICD-11 auto-coding outputs are explicitly flagged as requiring verification against the official WHO ICD-11 browser.
